# RU Liquidity Sentinel

RU Liquidity Sentinel рассчитывает ежедневный Liquidity Stress Index (LSI) для мониторинга напряженности на российском денежном рынке. Система объединяет данные по резервному усреднению, RUONIA, операциям РЕПО, первичным аукционам ОФЗ, налоговой сезонности, бюджетным потокам и банковской ликвидности.

Индекс предназначен для регулярного мониторинга, ретроспективного анализа стресс-периодов и оценки вклада отдельных источников давления. Результаты сохраняются в воспроизводимых артефактах и доступны через Streamlit-dashboard.

## Ключевые Возможности

- Ежедневный LSI в шкале 0-100 с зонами `green`, `yellow`, `red`.
- Инкрементальное обновление без полного переобучения при каждом запуске.
- NSVM-агрегатор на базе LSTM-модели аномалий.
- ECDF-калибровка с нейтральным и стрессовым квантильными якорями.
- Атрибуция вклада модулей M1-M5 в итоговый индекс.
- Автоматическое выделение аномальных периодов.
- Backtest по заранее заданным историческим эпизодам.
- Анализ чувствительности к ключевым гиперпараметрам модели.

## Архитектура

Процесс разделен на два режима.

### Первичная Инициализация

Команда `--init` выполняет полный расчет истории:

1. Загружает подготовленные CSV-файлы из `data/raw`.
2. Строит ежедневную матрицу признаков по модулям M1-M5.
3. Обучает NSVM на истории до `PipelineConfig.nsvm_init_cutoff_date`.
4. Калибрует сырые NLL-оценки модели в шкалу LSI.
5. Сохраняет модель, калибратор, исторический LSI и диагностические таблицы.

### Инкрементальное Обновление

Обычный запуск:

1. Загружает текущие веса NSVM и сохраненный ECDF-калибратор.
2. При необходимости подтягивает свежие данные через парсеры.
3. Рассчитывает новые дни с использованием исторического контекста.
4. Дописывает новые строки в историю LSI.
5. При выявлении существенного сдвига режима выполняет ограниченное `partial_fit`.
6. Пересобирает артефакты для dashboard.

## Методика Расчета

### Нормализация Признаков

Первичные ряды приводятся к ежедневной частоте и нормализуются через rolling MAD:

```text
z = (x - median) / (1.4826 * MAD)
```

Для показателей с односторонней стрессовой интерпретацией используется только соответствующий хвост распределения:

- `upper`: стресс растет при высоких значениях;
- `lower`: стресс растет при низких значениях;
- `two-sided`: учитываются оба направления отклонения.

Экстремальные значения ограничиваются causal winsorisation, чтобы единичные выбросы не искажали rolling MAD на длительном горизонте.

### CUSUM

Для ключевых рядов строится онлайн-накопитель устойчивого сдвига. Он использует только прошлые наблюдения, возвращает значение в диапазоне 0-1 и помогает отделять устойчивое давление от разовых публикационных скачков.

### NSVM-Агрегатор

NSVM-модель прогнозирует следующий вектор признаков по историческому окну `seq_len`. Отклонение факта от прогноза переводится в Gaussian NLL. Чем выше NLL, тем сильнее текущая конфигурация признаков отличается от нормального исторического режима.

Сырой NLL сглаживается EMA и затем калибруется через ECDF:

- `nsvm_lsi_q_low = 0.20` соответствует спокойной зоне и шкалируется к 0;
- `nsvm_lsi_q_high = 0.995` соответствует стрессовому хвосту и шкалируется к 100.

Такой подход не считает медианное историческое наблюдение стрессом и делает верхнюю часть шкалы более содержательной.

## Экономические Модули

### M1: Резервное Усреднение И RUONIA

Модуль оценивает дефицит резервов и отклонение RUONIA от ключевой ставки.

Основная стрессовая логика:

- дефицит резервов: `required_avg_blnrub - actual_balances_blnrub`;
- рост RUONIA относительно ключевой ставки;
- последние дни периода усреднения как календарный фактор.

### M2: Операции РЕПО Банка России

Модуль отражает спрос на ликвидность через первичные 7-дневные аукционы РЕПО.

Учитываются:

- cover ratio спроса к удовлетворенному объему;
- ставка размещения относительно ключевой ставки;
- флаг повышенного спроса;
- флаг операций fine tuning.

### M3: Первичные Аукционы ОФЗ

Модуль оценивает рыночное давление на первичных размещениях.

Стрессовые признаки:

- низкий cover ratio;
- рост доходности относительно локального уровня;
- недоподписка.

Высокая переподписка сама по себе не интерпретируется как стресс.

### M4: Налоговая Сезонность

Модуль описывает предсказуемую календарную нагрузку. Налоговые пики и периоды конца месяца/квартала/года используются как контекст, а не как самостоятельный рыночный шок.

В итоговом LSI предсказуемая налоговая неделя дополнительно смягчает сигнал на 20%, чтобы не завышать стресс по регулярным календарным причинам.

### M5: Бюджетные Потоки И Банковская Ликвидность

Модуль отслеживает изменение остатков, бюджетный drain и данные по размещению средств.

Стрессовая логика:

- снижение ликвидности банковского сектора;
- отрицательные 5-дневные изменения;
- признаки сильного бюджетного изъятия;
- снижение активности размещения временно свободных средств.

Требуется Python 3.10+.

```powershell

```

```powershell

```

make fetch

## Запуск

Первичная инициализация:

```powershell
py scripts/incremental_nsvm.py --init
```

Инициализация с явной датой cutoff:

```powershell
py scripts/incremental_nsvm.py --init --cutoff 2024-01-01
```

Инкрементальное обновление с загрузкой свежих данных:

```powershell
py scripts/incremental_nsvm.py
```

Инкрементальное обновление без запуска парсеров:

```powershell
py scripts/incremental_nsvm.py --no-fetch
```

Dashboard:

```powershell
py -m streamlit run dashboard/app.py
```

Тесты:

```powershell
py -m pytest -q
```

- `model_predictions.parquet`: линия NSVM для dashboard;
- `model_nsvm_module_attribution.parquet`: вклад модулей M1-M5;

## Конфигурация

Основные параметры находятся в `PipelineConfig`:

- `mad_window_days`: окно rolling MAD;
- `nsvm_init_cutoff_date`: граница обучающей истории;
- `nsvm_lsi_q_low`: нижний ECDF-якорь шкалы LSI;
- `nsvm_lsi_q_high`: верхний ECDF-якорь шкалы LSI;
- `nsvm_regime_nll_multiplier`: порог смены режима;
- `nsvm_partial_fit_epochs`: число эпох для дообучения при смене режима;
- `episode_min_days`: минимальная длина стресс-эпизода;
- `episode_top_k`: количество эпизодов для сохранения в отчет.

## Интерпретация LSI

По умолчанию используются зоны:

- `0-40`: green, нормальная или умеренная обстановка;
- `40-70`: yellow, повышенное давление;
- `70-100`: red, выраженный стресс.

LSI не является прогнозом ставок или ликвидности. Это композитный индикатор текущего режима, чувствительный к совместной динамике нескольких источников рыночного и календарного давления.

## Эксплуатационные Замечания

- После изменения логики признаков, модели или калибровки следует выполнить `--init`.
- Если артефакты старше кода модели, dashboard выводит предупреждение о необходимости пересборки.
- При изменении `nsvm_lsi_q_low` или `nsvm_lsi_q_high` инкрементальный контур автоматически инициирует пересборку.
- Перед интерпретацией новых сигналов стоит проверять вклад модулей и список auto-episodes, а не только итоговое значение LSI.
